Maqiri — Windows 11 開発・検証手順（SETUP_WINDOWS）
====================================================
対象: 開発者。利用者には Node.js / Git / ターミナルは不要です（インストーラーのみ）。

0. 記録
- 本文書の手順は Linux(Ubuntu, Node 22.22.0, npm 10.9.4, システム ffmpeg 6.1.1)上で 2026-10-05 に通したものを Windows 向けに書き起こしたものです。
- Windows 11 実機での検証日・結果は docs/TEST_REPORT.txt に記録します（未実施の項目は「未実施」と明記）。
- 使用版: Electron 44.5.1 / electron-vite 5.0.0 / Vite 7.3.6 / TypeScript 5.9.3 / Vitest 5.0.3 / Playwright 1.63.0 / electron-builder 26.15.3 / React 19.3.0 / Zustand 5.0.15 / Zod 4.6.5
- 同梱 FFmpeg: n8.1.3-14-g330caae0c1（BtbN win64-lgpl、autobuild-2026-10-05-13-07、LGPL v3）。詳細は media-tools.lock.json

1. 前提（開発機）
- Windows 11 x64、PowerShell
- Node.js 22 LTS x64（https://nodejs.org/）、Git for Windows
- ネットワーク: 初回の npm ci と media:prepare（GitHub Releases から約 170MB）にだけ必要。利用者の初回ネット接続は不要

2. 取得と依存
    git clone <repo> maqiri
    cd maqiri
    npm ci
  ※ npm install ではなく npm ci を使い、package-lock.json を正本にする。

3. 同梱メディアツール（FFmpeg LGPL ビルド）
    npm run media:prepare
  - media-tools.lock.json の URL から zip を取得し、zip と展開後の ffmpeg.exe / ffprobe.exe / LICENSE.txt の SHA256 を検証します。
  - 対応ソース（FFmpeg のコミットと BtbN ビルドスクリプト）を git archive で resources/media-tools/source/ に生成します（git が必要）。
  - ハッシュ不一致なら停止します。ロックの値を書き換えて通さないこと。
    npm run media:verify   … 既存ファイルの検証のみ

4. 実機でのエンコーダー確認（開発初日に必ず）
    .\resources\media-tools\win32-x64\ffprobe.exe -version
    .\resources\media-tools\win32-x64\ffmpeg.exe -h encoder=h264_mf
    .\resources\media-tools\win32-x64\ffmpeg.exe -f lavfi -i testsrc2=s=1920x1080:r=30:d=2 -c:v h264_mf -hw_encoding 0 -rate_control pc_vbr -b:v 12M -maxrate 15M -bufsize 24M -g 60 -bf 0 -profile:v high -scenario camera_record -pix_fmt yuv420p -f mp4 -y t.mp4
    .\resources\media-tools\win32-x64\ffmpeg.exe -i t.mp4 -f null -
  - 成功した設定（variant）を docs/TEST_REPORT.txt に記録。失敗する場合は src/media/encoder.ts の variants の順に試し、順序を実機結果に合わせる。
  - アプリは起動時に同じ 2 秒テストを実行し、失敗時は E_ENCODER を表示します（別コーデックへ黙って変えません）。

5. 検証と起動
    npm run typecheck
    npm test             … ドメイン/単体（Vitest）
    npm run test:media   … fixture 生成（lavfi）+ 実 ffmpeg 統合テスト
    npm run build        … サンプル生成 + electron-vite build
    npm run test:e2e     … Electron 実起動（Playwright）: S0 → サンプル → 解析 → 保持/Undo → つなぎ目 → 書き出し → S4
    npm run dev          … 開発起動（HMR）。UI だけの browser preview はネイティブ起動成功とは見なさない
  - Electron を起動して実動画を選び、編集・書き出しできるところまで確認する（AC01 相当の手動確認）。

6. 配布ビルド（Windows 上で実行）
    npm run dist:demo    … release/demo/Maqiri-Demo-Setup-x64.exe + SHA256SUMS.txt
    npm run dist:full    … release/full/Maqiri-Full-Setup-x64.exe + SHA256SUMS.txt
  - NSIS、x64、per-user、管理者権限不要（requestedExecutionLevel=asInvoker）
  - 署名: 証明書がある場合は環境変数 CSC_LINK（.pfx のパス）と CSC_KEY_PASSWORD を設定して実行。無ければ未署名と記録（RELEASE_CHECKLIST E）
  - APP_EDITION は dist スクリプトが設定し、ビルド時 define（__APP_EDITION__）で main に埋め込まれる。DEMO の 90 秒制限は main 側で強制

7. 開発時の注意
- Linux/macOS では h264_mf が無いため、テストはシステム ffmpeg の libx264 を「dev encoder」として使う（配布しない）。MAQIRI_FFMPEG / MAQIRI_FFPROBE でパスを上書き可。
- E2E は非パッケージ版のみ有効な環境変数 MAQIRI_E2E_EXPORT_DIR / MAQIRI_E2E_USER_DATA でネイティブダイアログを回避する。
- 秘密値を要する作業（署名）は必須手順に含めない。
