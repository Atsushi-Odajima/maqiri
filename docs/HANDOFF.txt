最優先の引き継ぎ事項（Codex 等に渡すとき）
1. main / renderer 分離: レンダラーに Node・任意ファイル読み込み・絶対パスを渡さない。assetId / jobId / token で main が実体を解決する（src/main/assets.ts, protocol.ts, ipc.ts）。
2. frame 正本: 保存・判定・書き出しは 30fps の整数フレーム半開区間 [startFrame, endFrame)。秒の小数表示を正本へ逆変換しない（src/domain/time.ts）。
3. 共有 T0: 最初に表示される映像フレームの PTS を T0 とし、映像・音声を同じ T0 へ正規化する。音声に STARTPTS を使わない（src/media/filters.ts, analysisWorker.ts）。解析と書き出しは同じ正規化関数を使う。
4. 元素材不変: 元ファイルへ書き込まない。出力は同 volume の一時ファイル → ffprobe 検証 → atomic rename。失敗時は一時ファイルを消し、完成名を作らない（src/main/controller.ts startExport）。
5. privacy: 外部送信なし、ログはパス/ユーザー名をマスク、音声・フレームはログに含めない（src/main/log.ts, src/media/process.ts maskPaths）。

既知の制約・注意
- 書体は assets/fonts から electron-vite の renderer publicDir として配信する(resources/fonts へは複製しない。仕様の「resources/fonts/：同梱assets/fonts」は assets/fonts → out/renderer/fonts の配信で満たす)。NotoSerifJP は 13.5MB あり、S0 の宣言見出しだけに使うためサブセット化が将来の最適化候補。
- Linux の dist は NSIS 段階で wine が無く失敗する。Windows 上で npm run dist:* を実行すること（win-unpacked の構成は確認済み）。
- 署名なし。SmartScreen 警告を回避できると約束しない。
- HEVC 入力はブラウザ再生できないことがあるため 720p proxy を自動生成（preview:render kind=proxy）。proxy 生成中は元ファイルを直接再生しようとして失敗することがある（表示は注記のみ）。
- 常時 BGM / 大きな環境音では無音を検出できない（constant_bgm fixture で確認済みの限界）。
- 候補端点の調整は保持(keep)と延長(manualCut)の組み合わせで表現し、延長は再解析後に quiet run 外なら破棄して通知する。
- 日本語自録 5 本による耳での品質確認は未実施（人工 fixture のみ）。『自然な日本語品質合格』とは言えない。
- 性能の広告用数値は Windows 実機の計測のみ使うこと。Linux の参考値は TEST_REPORT に明記。
