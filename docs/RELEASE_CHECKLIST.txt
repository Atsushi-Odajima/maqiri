Maqiri リリースチェックリスト（RELEASE_CHECKLIST）
===================================================
各項目は実施者・日付・結果を記入してからチェックすること。未実施を「済」にしない。

A. 開発環境（Windows 11 x64）
[ ] Node.js 22 LTS x64 / npm 10 / Git をインストール（利用者には不要）
[ ] git clone → npm ci（package-lock.json で固定。npm install は使わない）
[ ] npm run media:prepare → media-tools.lock.json の SHA256 と一致し、resources/media-tools/win32-x64 に ffmpeg.exe / ffprobe.exe / LICENSE.txt / manifest.json が出来る
[ ] resources/media-tools/source に ffmpeg-330caae0c1.tar.gz と ffmpeg-builds-scripts-*.tar.gz が出来る

B. 固定 FFmpeg ビルドの Windows 実機確認（lock の windowsRuntimeVerification を PERFORMED に更新する前提）
[ ] resources\media-tools\win32-x64\ffprobe.exe -version → n8.1.3-14-g330caae0c1-20261005
[ ] ffmpeg.exe -h encoder=h264_mf → rate_control(default/cbr/pc_vbr/u_vbr/ld_vbr/g_vbr/gld_vbr), scenario, quality, hw_encoding が表示される
[ ] ffmpeg.exe -f lavfi -i testsrc2=s=1920x1080:r=30:d=2 -c:v h264_mf -hw_encoding 0 -rate_control pc_vbr -b:v 12M -maxrate 15M -bufsize 24M -g 60 -bf 0 -profile:v high -scenario camera_record -pix_fmt yuv420p -f mp4 t.mp4 → 成功
[ ] 上記が失敗した場合: -scenario なし → cbr → default の順で確認し、成功した variant 名を docs/TEST_REPORT.txt に記録（src/media/encoder.ts の順序と一致させる）
[ ] HEVC 8bit fixture のデコード（ffmpeg -i hevc_8bit.mp4 -f null -）
[ ] aac 48kHz stereo/mono エンコード
[ ] 結果を docs/TEST_REPORT.txt「Windows 実機」節へ記録し、media-tools.lock.json の windowsRuntimeVerification.status を "PERFORMED" + 日付 + 機材に更新

C. 自動テスト（Windows 実機）
[ ] npm run typecheck
[ ] npm test（ドメイン/単体）
[ ] npm run test:media（fixture 生成 + 実 ffmpeg 統合: probe / 解析 / 書き出し検証 / 同期マーカー / 600 カット / キャンセル / つなぎ目）
[ ] npm run build → npm run test:e2e（Electron 実起動: S0 → サンプル → 解析 → 保持/Undo → つなぎ目 → 書き出し → S4）
[ ] 結果（合格/不合格/未実施、機材、日付）を docs/TEST_REPORT.txt に記録

D. 手動受け入れ（AC01〜AC12、第 12 節 F/G）
[ ] 実動画（自録 5 本、許諾済み）で読込→解析→つなぎ目試聴→保持→書き出し。自然な日本語品質は耳で確認（人工 fixture だけで合格にしない）
[ ] 960×700 / 1280×800 / 1440×900 / 200% ズームで欠けがない。Tab 順、フォーカス復帰、warning の非色依存
[ ] 全無音 / 音声なし / HDR / 破損 / 4K / MKV の拒否表示と戻り先
[ ] 容量不足（小さなドライブ/USB）/ 読み取り専用保存先 / 同名パス / 長い日本語パス・絵文字 / " と & を含むファイル名
[ ] キャンセル・強制終了後に元動画と完成済み出力が無事、.maqiri-tmp が残らない
[ ] 性能計測: 同一機材で 10 分 1080p の解析秒数 / 書き出し秒数 / peak RSS（タスクマネージャー or Get-Process）を TEST_REPORT に記録。広告用の速度はこの実測のみ使う

E. 配布ビルド
[ ] npm run dist:demo / npm run dist:full（Windows 上で実行。media:prepare の --verify-only が自動で走る）
[ ] release/demo, release/full に Maqiri-Demo-Setup-x64.exe / Maqiri-Full-Setup-x64.exe と SHA256SUMS.txt
[ ] インストーラーが per-user、管理者権限を要求しない。アンインストールでアプリのみ削除（プロジェクト/元素材/userData は残る）
[ ] 配布物内に media-tools/（ffmpeg.exe, ffprobe.exe, LICENSE.txt, manifest.json, media-tools.lock.json, source/*.tar.gz）、docs/（START_HERE_JA, FORMAT_LIMITS, EULA_DRAFT, THIRD_PARTY_NOTICES, CHANGELOG, FFMPEG_LICENSE_LGPLv3）、sample/sample_10s.mp4 がある
[ ] LGPL 対応ソース: 全依存ライブラリのソース集合を用意する場合は BtbN の scripts.d/ が取得する版を収集して media-tools/source/ に追加（または書面による提供申し出を EULA に記載）
[ ] 署名: コード署名証明書がある場合は CSC_LINK / CSC_KEY_PASSWORD を設定して dist を再実行し、signtool verify /pa で確認。無い場合は「未署名」と CHANGELOG / START_HERE_JA に明記（SmartScreen 回避を約束しない。Defender 無効化手順は書かない）

F. リリースゲート（別のクリーン Windows 11）
[ ] Node / ffmpeg 未導入、ネット切断状態でインストール → 起動 → 同梱サンプル 10 秒の 90 秒体験（読込→解析→試聴→書き出し→再生）が完了
[ ] DEMO が先頭 90 秒を超えない（90 秒超の動画で確認）。FULL は 30 分上限まで処理
[ ] SHA256SUMS.txt のハッシュとインストーラーが一致

G. 販売準備
[ ] HANDOFF.txt の「未達 AC」が空、または販売判断者が承知の上で記録済み
[ ] EULA_DRAFT の法務確認
[ ] 販売ページの速度・短縮量は TEST_REPORT の実測だけを使う。「字幕」「フィラー削除」「意味理解」「唯一の買い切り」「完全自動」を書かない
